# UX 评审量表（人读版）

机器可读的唯一真源是 `design-systems/rubrics/ux-review.json`（构建后进 `dist/design/rubrics/`）。
本文件是给代理与评审者看的使用说明；两者冲突时以 JSON 为准。

`canvas_audit`（`action=ux`）会按三段式把这个量表交给你：先出截图与空模板，你回填，再跑确定性检测，最后算分。

---

## 一、设计特异性（第一输出项）

写任何评分之前先回答这三问，并给证据：

1. 盖住产品名，这还能看出是哪个类别吗？
2. 邻近产品能否原样使用这套设计？
3. 这里有什么是通用模板无法声称的？

判词写一句话，证据至少一条。**这一项先于所有其他判断**，因为一个"精致的通用后台"在每一项启发式上都可能拿到 3 分。

---

## 二、10 条启发式（每条 0–4）

诚实校准：**4 分表示真正优秀，不是"够用"**。多数真实界面落在 20–32 / 40。

| # | 启发式 | 0 分 | 2 分 | 4 分 |
|---|---|---|---|---|
| 1 | 系统状态可见性 | 没有任何反馈，用户只能猜 | 部分反馈，主要状态有、重大缺口仍在 | 每个动作都有确认，进度始终可见 |
| 2 | 符合现实世界 | 纯技术行话，对用户完全陌生 | 混杂，有通俗语言也有行话泄漏 | 全程使用用户的语言 |
| 3 | 用户控制与自由 | 用户被困住，除了刷新没有出路 | 主要流程有出口，边界情况没有 | 撤销、取消、返回、退出处处都有 |
| 4 | 一致性与标准 | 到处不一致，像不同产品拼起来的 | 部分一致，主流程一致、细节分歧 | 完全一致，系统内聚、行为可预测 |
| 5 | 错误预防 | 很容易出错，没有任何护栏 | 部分预防，常见错误能挡、边界漏掉 | 靠智能约束让错误几乎不可能发生 |
| 6 | 识别优于回忆 | 重度依赖记忆，用户必须记住路径 | 有一些辅助，主要动作可见、次要功能隐藏 | 一切可发现，用户无需记忆 |
| 7 | 灵活与效率 | 只有一条死板路径 | 有一些捷径，基础键盘支持 | 多条路径、高级功能、可定制 |
| 8 | 美学与极简 | 所有元素同等抢注意力 | 有些杂乱，主体清晰、边缘嘈杂 | 每个元素都挣到了它的像素 |
| 9 | 错误识别与恢复 | 只有错误码或什么也没有 | 清楚但无用，说明问题却没给解法 | 定位问题、建议修法、保留用户已做的工作 |
| 10 | 帮助与文档 | 任何地方都没有帮助 | 有 FAQ 或文档但不结合上下文 | 在对的时刻给出对的信息 |

完整 0/1/2/3/4 判据、每条的 `checkFor` 清单在 JSON 里。

### n/a 规则

- **只有第 7 条（灵活与效率）与第 10 条（帮助与文档）可以标 n/a**，用于 persuade / experience 这类落地页。
- 标 n/a 必须写理由。
- **分母重算**：9 项计分 → 满分 36，不是 40。报告里写 `27/36`，绝不写 `/40`。
- 档位按**百分比**判：90%+ 优秀、70%+ 良好、50%+ 可接受、30%+ 较差、更低为严重。
- 有效分母低于 24 分时工具会警告"代表性不足"，你需要在报告里说明为什么这些项不适用。

## 三、认知负荷（8 项清单）

逐项判断是否失败；**记录失败项的 id**，工具据此给档位（≤1 低 / ≤3 中 / ≥4 高）。

| id | 项目 | 判据 | 失败表现 |
|---|---|---|---|
| `single-focus` | 单一焦点 | 能不受竞争元素干扰完成主任务吗 | 竞争元素把注意力拉走 |
| `chunking` | 分组 | 每组 ≤4 项吗 | 分组超过 4 项 |
| `grouping` | 归组 | 相关内容视觉上聚在一起吗 | 相关内容散落 |
| `hierarchy` | 视觉层级 | 一眼能看出什么最重要吗 | 看不出重点 |
| `one-at-a-time` | 一次一件事 | 能专注一个决策再进下一个吗 | 同时要求多个决策 |
| `minimal-choices` | 最少选项 | 每个决策点 ≤4 个可见选项吗 | 超过 4 个 |
| `working-memory` | 工作记忆 | 需要记住上一屏的信息吗 | 必须跨屏记忆 |
| `progressive` | 渐进披露 | 复杂度只在需要时展开吗 | 一开始全给 |

**工作记忆法则**：人一次只能保持 ≤4 项。超过就分组或渐进披露；到 8 项以上，用户会跳过、误点或放弃。

## 四、persona 走查（选 2–3 个）

| 界面类型 | 建议 persona |
|---|---|
| 落地页 / 营销 | 困惑的新手、刻意施压者、分心的手机用户 |
| 仪表盘 / 后台 | 高效老手、依赖无障碍的用户 |
| 电商 / 结账 | 分心的手机用户、刻意施压者、困惑的新手 |
| 引导流程 | 困惑的新手、分心的手机用户 |
| 数据密集 / 分析 | 高效老手、依赖无障碍的用户 |
| 表单密集 / 向导 | 困惑的新手、依赖无障碍的用户、分心的手机用户 |

### 五个人物

- **高效老手（alex）**：用过同类产品，期待效率、讨厌被手把手教。
  红旗：强制教程、主操作没有键盘路径、无法跳过的慢动画、本可批量却只能一条条做、低风险动作也要重复确认。
- **困惑的新手（jordan）**：从没用过这类产品，宁可放弃也不愿琢磨。
  红旗：纯图标导航、行话没解释、没有帮助入口、动作后下一步含糊、成功却没确认。
- **依赖无障碍的用户（sam）**：读屏 + 纯键盘，可能有低视力或运动障碍。
  红旗：只能点击、焦点指示缺失、仅用颜色传达、控件没有可访问名、限时无延长、自研组件破坏读屏流程。
- **刻意施压者（riley）**：试边界、喂异常输入、找承诺与行为的落差。
  红旗：看起来正常却静默失败、错误处理暴露技术细节、空状态没信息、刷新丢数据、相似交互行为不一致。
- **分心的手机用户（casey）**：单手、随时被打断、可能慢网。
  红旗：重要操作在屏幕顶部、没有状态保留、本可选却要大段输入、每页加载重型资源、触控目标太小。

**写法**：不要写人设描述，写"具体哪一处对这个人失效"。例如"表格表头不可聚焦，Sam 无法排序"，而不是"Sam 需要无障碍"。

## 五、优先级问题（3–5 条，挂 P0–P3）

| 级别 | 名称 | 判据 | 处置 |
|---|---|---|---|
| P0 | 阻塞 | 完全无法完成任务 | 立即修复 |
| P1 | 重大 | 造成明显困难或困惑 | 发布前修复 |
| P2 | 次要 | 令人不快，但有绕过办法 | 下一轮修复 |
| P3 | 打磨 | 可以更好，对用户没有实质影响 | 有余力再做 |

犹豫时问：**用户会为此联系客服吗？** 会，则至少 P1。

每条必须写清三件事：**是什么问题 / 为什么伤害用户 / 怎么改**。

## 六、审美下限（九项，判断时对照）

1. 正文与占位符对比度 ≥4.5:1；大字 ≥3:1；彩色表面上的次要文字从该色相或前景取色，**不用灰**。
2. 阴影必须带偏移与柔和模糊；零偏移的彩色光晕是装饰。
3. 相关项紧凑、不同组之间宽松；**标题上方间距大于下方**；读计算值而不是目测。
4. 正文行宽 65–75ch；display 字号上限 6rem；负字距下限 -0.04em；标题平衡；字号与字重阶梯明显。
5. 动效：一个亲手设计的时刻，不是每段相同的入场；从已可见状态出发的自然减速；不只用 transform 与 opacity。
6. 状态：hover、disabled、loading、error、empty 齐备；再加真实内容、可用控件、响应式构图、键盘焦点。
7. 浏览器表面：选区、光标、滚动条、焦点环、下划线偏移、表格等宽数字都按调色板主题化。
8. 文案：控件名称说明动作；错误说明问题与恢复方式。
9. 覆盖：简报里的每一项都在页面中，且几秒内能找到。

## 七、硬禁令 vs 默认值

**只有一条硬禁令**：标题上方的 eyebrow / kicker 小标签。任何简报都换不回来 —— 标题自己扛重量，删掉标签让标题说话。

其余都是**默认值**，简报的明确文字可以换回来：同尺寸卡片网格作页面骨架、hero 大数字模板、区块编号、无必要弹窗、渐变文字、装饰性毛玻璃、圆角容器上的单边色条、硬偏移阴影、假 sparkline / 进度环、把等宽字体当技术感戏服、系统 display 字体、emoji 冒充图标、几何遮罩冒充有机轮廓、按类别而不是使用场景选明暗。

判断的区别：**硬禁令**无论简报怎么写都是错的；**默认值**是"你没有在决定"时的答案，一旦简报给出理由就成立。

## 八、报告骨架（`phase=synthesize` 会给你）

```
方法：三段式隔离（A 设计评审先行完成；B 确定性检测 <时间>）
## 设计健康度         ← 10 行表 + 合计 N/M · 百分比 · 档位
## 设计特异性         ← A 的判词与证据
## 认知负荷           ← 失败项与档位
## A 与 B 的交叉核对   ← 你填：都指出的 / B 抓到 A 漏掉的 / B 的误报
## 确定性检测（B）     ← 契约、a11y、工艺、渲染审阅的数字
## 优先级问题         ← P0–P3 排序 + 计数
## persona 红旗
## 做得好的地方
## 未测项与限制
```

**不要写**：把 /40 当合格证、把自动检测当成审美通过、替你填用户的评审结论。
