# 天枢画布设计 v0.7.2

> 2026-11-06 · Apache-2.0

修复**技能流程契约失效**——真机实测暴露的两个症状：Agent 不先给画布 UI 链接、
设计需求模糊时不自选风格也不询问，而是**自己挑了一套**。

根因不在插件逻辑，而在**约束放错了层**。

---

## 根因

天枢的技能（skill）是**懒加载**的：宿主只把每个技能的一行 `description` 注入系统提示里的
`<available-skills>` 块，**正文（SKILL.md 的 Markdown）只有在模型主动调用 skill 工具去 load 时才读**。

本插件的 SKILL.md 正文有 10898 字符，里面写着「执行顺序（严格按序，不得跳步）」——
① 先 `canvas_open` 把链接发给用户 → ② 再确认设计风格 → ③ 最后才写原型。
但这套硬约束**只存在于正文**，而模型的这次运行**从未 load 过该技能**，于是：

- 它只看到一行 48 字的 description：「用无限画布承载前端设计原型……」，里面没有任何顺序要求；
- 于是按自身直觉走：先查状态 → 自行挑风格 → 先把页面写完 → 最后才补 `canvas_open`。

**实测证据**（会话 `20261106a5563c759ed7`）：

| 检查项 | 结果 |
|---|---|
| frozen prompt 里 `<available-skills>` 块 | 1482 字符，tianshu-canvas 仅占 112 字符 |
| `执行顺序` / `canvas_open` / `这次用哪种风格` 出现次数 | 全部为 **0** |
| 是否调用过 `skill(name=...)` | **没有** |
| 实际调用顺序 | `10:55` get_state → `10:55` style → `10:59:00` **upsert_page（先写页面）** → `11:00:14` **canvas_open（才给链接）** |

第二个诱因：跨会话记忆里存在上一轮的「风格走苹果风，主色 #0071e3」，
模型据此认为风格**已被指定**（按规则此时确实不该问），进一步掩盖了问题。

## 修复

把顺序契约从**懒加载的正文**下沉到**始终在上下文的两层**：工具描述与参数描述。

### 1. 工具描述（永远注入）

| 工具 | 新增约束 |
|---|---|
| `canvas_open` | **【第一步】**……必须先把该 URL 单独一行发给用户，再开始设计 |
| `canvas_upsert_page` | ……调用前必须先 canvas_open，并已确认设计风格 |
| `canvas_style` | ……用户未指定风格时先用 action=list 列出并把风格名作为选项问用户一次，等回答后再继续 |

### 2. 参数描述（永远注入）

| 参数 | 新增约束 |
|---|---|
| `canvas_style.stack` | **多端导出前必须先问用户选哪种技术栈并等回答，不得替用户决定**（也可多选多端） |
| `canvas_design_system.dry_run` | 建议默认先传 true 让用户确认后再正式执行——正式执行会创建风格并重写所有页面 |
| `canvas_design_system.action` | create 前必须先**一次性**问清配置并等回答（配色/圆角/字号/字体/动效/阴影/控件尺寸/深色），不要拆成多轮反复追问 |

### 3. 技能 description

同步压入硬顺序（该行必定注入）：

```
前端设计原型写入无限画布。硬顺序：先 canvas_open 发链接给用户，再 canvas_style list 问风格并等回答。
```

## 覆盖度

修复后，所有「要求 AI 主动询问用户」的约束都有了始终注入的兜底：

| 询问点 | 兜底位置 |
|---|---|
| 风格（未指定时问一次） | 工具描述 + 技能 description |
| 自定义设计系统的 8 项配置 | `action` 参数描述 |
| codegen 导出「目标」 | `action` 参数描述 |
| codegen 多端「技术栈」 | `stack` 参数描述 |
| extract / import 先 `dry_run` 预览 | `dry_run` 参数描述 |
| 视觉基线团队共享目录 | `baseline_dir` 参数描述（原有） |

## 兼容性

- **无接口与数据变更**：只改了工具描述文本与技能 description，工具名、参数、行为、项目数据格式全部不变。
- 工具描述仍全部 ≤ 200 字，运行时与清单描述逐字一致（官方握手按 `{name, description}` 深比较）。
- `<available-skills>` 注入块占用 1482 → **1489 / 1500 字符**，未把其它技能挤出列表。
- **需重装插件 + 新建会话**才生效（天枢的插件与技能变更不热加载）。
