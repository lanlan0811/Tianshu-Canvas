# 天枢画布设计 v0.9.4

> 2026-11-12 · Apache-2.0

本版修复画布键盘操作、写入错误反馈、并发更新、容量边界和导航回填。项目格式保持 v1，沿用现有目录和九个顶层工具，无存储迁移。实际验收与发布门禁见本文末尾及本版验收记录。

## 画布与错误处理

- 为缩放、节点工具栏等纯图标按钮提供可访问名，为重命名输入提供标签；补齐画布外壳控件与可聚焦节点的可见焦点。保留顶栏已有可见文字。
- 导出菜单同步展开状态，支持 Esc 关闭和焦点返回；键盘、鼠标、缩放、节点编辑一并回归。
- 页面重命名、移动、复制与批注失败时显示错误并重新核对服务端状态，不自动重试可能重复执行的操作。
- 九个工具和 HTTP 共用错误格式化：输入错误 400、路径边界 403、工作区锁争用 409、最终 HTML 超限 413、未知故障 500。可修复错误给出中文原因与操作指引，未知文件错误不向调用方返回原始绝对路径，详细诊断进入宿主日志。
- 自动发现及显式读取使用经文件身份核对的描述符，收紧检查后路径被替换的读取窗口；继续保留鉴权、CSRF、SSRF、Windows junction 和 Chromium 沙箱防护。

## 工作区写入与容量

- 工作区内独占创建 .tianshu-canvas/project.lock。锁覆盖读取最新项目、校验、页面写删与项目提交；内部调用显式复用同一同步事务。网络抓取和资源内联在取锁前完成，恢复后依据锁内最新状态决定标题、布局、风格与导航。
- 单次事务复用项目模型、健康检查及原始 Buffer，普通批次仅检查一次项目文件，批量最多提交一次 project.json。项目损坏或含无效条目时，只读不改盘；显式修复性写入先备份本次读取的原始字节，视口等隐式操作不覆盖损坏文件，简报和换肤要求先修复。
- 最终落盘 HTML 按 UTF-8 字节计，单页最多 8 MiB（8,388,608 字节），包含资源内联、导航改写和设计注入。项目最多 1000 页，复制、工具和 HTTP 入口共用限制。
- 批量先计算或暂存并统一校验，再发布正式文件；容量或输入校验拒绝时，项目、页面、自定义风格和品牌记忆不留下部分更新。HTML 使用独占随机临时文件加 rename 发布。
- 旧版超限项目仍可读取、删除、减少数量及进行不重写 HTML 的元数据操作；主动提供或重写的 HTML 必须降至限额，不能通过复制绕过。旧超限页面自动补齐后仍超限时保留原文和 HTML 版本，并明确告警。
- 锁以随机标识和文件身份确认所有权，异常经 finally 释放；畸形、链接、被替换或被篡改的锁不会自动删除，不按 PID 或时间自动抢占。争用立即失败并提示重试，不持锁等待网络或阻塞轮询。

## 导航与性能边界

- 新增独立导航模块，按工作区维护派生的引用反向索引，单批共享 ID 与标题 slug 解析索引。创建、改名、复制、删除选择受影响来源页，HTML 更新重建本页索引，移动和尺寸调整不读取其他页面正文。
- AI 工具与画布 HTTP 入口使用同一事务内回填，受影响 HTML、版本与模型一起提交。最终 HTML 字节相同则不写文件、不递增 htmlRev，也不因该页面正文触发 iframe 刷新。
- 外链、锚点、脚本、样式与注释保持原样；来源页存在歧义时整页保留，告知用户改用页面 ID 或 data-nav。缓存仅在提交成功后发布，冷启动可全量建立，后续按 dev/ino、时间和大小指纹识别外部修改，最终插件实例退出时清理。
- 保留既有 ID 优先规则：现存 ID 不因改名或同名标题重新绑定。项目 v1 没有持久化链接来源标记，普通 href 的 ID 被删除后，若恰有相同字面值的标题 slug，仍可回退到该页；热缓存与冷启动行为一致。需要精确 ID 且删除后不回退的引用使用 data-nav。
- 优化目标是减少重复正文读取、解析和落盘，不宣称整体写入 O(1)。项目解析和指纹检查仍可能随页数增长；本机候选 50/200/1000 页各三轮样本中，1000 页更新仍可达到数秒级。性能样本与最终冻结产物的对应关系、耗时和限制均见验收记录，不将候选样本冒充最终版本性能保证。
- 200 节点真实浏览器首屏与内存作为边界记录，节点出现不等于所有 iframe 完成渲染。本版不引入 iframe 虚拟化，也不据交错系统负载测量声称首屏性能提升。

## 升级、数据与恢复

- 从 0.9.3 升级无需迁移；更新插件后重新创建会话并打开画布。Node 仍为 >=24.22.1 <27；平台与宿主支持声明不扩大，实际验证版本以本版记录为准。
- project.json、页面 HTML、简报、批注、自定义风格和品牌记忆是工作区内的明文文件，插件不为这些文件提供加密；gitignore 不能替代访问控制或加密。不要在原型和批注中保存令牌、密钥或敏感真实业务数据，备份及导出也需自行保护。
- 遇到持续锁争用，先保存工作并关闭使用该工作区的全部天枢、插件宿主和测试进程，确认没有写入者后，人工移除 .tianshu-canvas/project.lock，再重新打开并重试；运行中的宿主持锁时不要清锁。
- 遇到 project.json 损坏，优先保留原文件并修复 JSON、无效节点或简报；需要恢复时先关闭相关写入进程并备份当前数据，再核对 project.json.corrupt-* 备份。恢复后重新打开画布检查页面和关联信息。
- 工作区锁协调合作插件进程的读改写互斥，不保证外部编辑器互斥、多文件断电或崩溃回滚，也不提供跨进程实时广播。HTML 单文件原子替换不等于整个项目多文件事务的崩溃恢复。
