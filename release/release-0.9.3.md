# 天枢画布设计 v0.9.3

> 2026-11-11 · Apache-2.0

本版把默认生成流程从选择风格名，改为先整理内容、比较两个首屏，再沿用户确认的方向完成整页。技术交付与人工审美结论分别记录；本版不宣称已证明优于直接生成。

## 新增能力

- **视觉方向与原创原型**：编辑叙事、产品证据、品牌海报三类方向各提供中英示例，共六份。32 个共享原型覆盖营销内容、企业后台、AI/知识、移动应用、IDE、设置和方案文档；与原有 11 套 token 风格、dashboard/landing 旧模板分离。
- **双首屏选稿**：更新默认技能与工具提示，指导 AI 用同一内容展示两个不同构图的普通画布节点；这是一条生成工作流，不是自动生成引擎或 UI 强制门禁。用户明确选择后，在原节点完成整页和移动端，另一方案保留。指定品牌、风格和布局优先，应用界面按任务组织。
- **页面简报**：`canvas_style` 增加 `direction`、`prototype`、`brief`，九个顶层工具不变。简报记录受众、主张、证据、行动及显式确认方向与理由；选中节点不等于确认。复制保留原记录，删除清理关联数据，旧项目无需迁移。
- **渲染审阅**：`canvas_audit action=review` 生成 1440/768/390 三尺寸截图、页面 SHA256 与客观问题报告；每个视口最长 16000px，超限明确告警，原型库验收另要求完整高度。沿用真实鉴权、opaque iframe 和 Chromium 沙箱；截图不等于自动审美评分。

## 交互与安全

- 新增声明式本地筛选、计数、分页、批量归档演示、聊天演示、表单反馈、配置联动和工作台定位；保留真实点击与键盘操作，不连接后端。
- 修复沙箱无 `allow-forms` 时本地表单操作、嵌套过滤隔离、聊天容器串扰，以及筛选复位后分页使用旧状态的问题；尊重禁用控件和输入法组合输入。
- 原型资源拒绝脚本、外链、未登记类及遗漏的候选图片/媒体封面/导航追踪通道；不引入外部字体、CDN、遥测或新权限。
- 修复 Tailwind 配置字符串拼接的源码注入风险，键和值统一转义。React 导出保留局部布局 CSS，脚本行为仍需在 React 中实现和验收。
- 审阅等待目标页面已提交导航的真实 iframe，再核对容器、URL 和就绪状态，避免使用初始空文档；连续多页与回访截图核验页面像素。

## 验收与发布

Windows 严格浏览器全量验收 **237/237通过，0失败、0跳过**；类型、构建、许可一致性、桩与真实依赖代码生成编译、插件自检均通过。38份资源、114张三尺寸截图完整生成，0客观失败，源码与dist逐字节核对且截图期间指纹不变。候选语义警告和固定底栏拼接伪影保留记录，未作为审美通过。最终结果与限制记录在 `docs/aesthetic-upgrade-acceptance.md`。

CI 与 Release 都执行全原型截图门禁，核对当前源码与 `dist`、页面哈希、三个视口和完整高度，保存可下载的 Actions 验收证据。发布必须由 `.github/workflows/release.yml` 执行，并复核同一 SHA 的 main push CI 成功；发布说明读取本文件。

## 升级与限制

- 从 0.9.2 升级无需数据迁移；更新插件后新建会话并重新打开画布。平台与宿主兼容范围不变。
- 所有示例中的业务数据及 SVG/CSS 产品画面均为演示，不可用作真实产品截图或经营证据；复杂原型不提供真实业务后端。
- 本地研究完成 16 库、33 份来源与 152 份组件预览的逐项处理；来源代码与未核实许可素材不进入发行包。两份 IDE 来源合并为一个目标，不能把来源数量当作产品数量。
- 两组六题匿名审美对照目前仅准备固定输入与公平条件，独立成稿生成、所有者选稿反馈和评分仍待完成；天枢宿主手工读图亦未完成。当前只认定技术交付，不宣称整体审美验收完成。
- 固定/粘性元素、动态内容可能影响滚动拼接，内部滚动区域仅记录当前状态；超出截图限制会明确告警或失败。
